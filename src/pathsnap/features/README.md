# Shared candidate features

`build_feature_table` outputs `trip_id`, `observation_id`, `arc_id`, `distance_m`, `heading_difference`, `speed_mps`, and `time_gap_s`, plus candidate diagnostic `search_expanded`. The diagnostic is not a model feature. `heading_difference` is in degrees, the absolute wrapped difference in [0, 180] between movement heading and the directed segment vector (`from_node_id` to `to_node_id`). Movement heading is clockwise from north in the supplied x/y axes. First-observation/invalid/nonpositive gaps use 0 seconds; stationary displacement has 0 m/s and neutral 0 degree heading difference; zero-length segments have neutral 0 degree difference. Non-finite numeric results are replaced with 0. This explicit neutral-value policy makes the table directly usable by Logistic Regression and Random Forest without learned imputation. Any scaling/imputation fitted downstream must use training data only.

IDs and `alignment_status` are metadata, never model input. `attach_reference_labels` labels only statuses configured as reliable (default normalized values: `aligned`, `reliable`, `ok`) and leaves others null. The recorded training run explicitly permits only Part 1's `aligned` status. `reference_candidate_coverage` returns one row per reference observation, including zero-candidate observations and reliable references missing from the candidate set; labels never alter candidates. Its `candidate_count`, `has_candidates`, and `reference_arc_missing` fields preserve zero-candidate failures. The CLI saves this enriched table separately as `*_supervised.csv`, keeping the shared feature table free of labels.

Observation movement is calculated in original source order. Nonpositive time
steps receive neutral speed/heading/time-gap features rather than being hidden
by timestamp sorting. Empty candidate tables attach labels without crashing.
